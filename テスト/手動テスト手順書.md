## この文書の位置づけ

`テスト項目一覧.md` の「3. 結合テスト(業務シナリオ・手動)」を、画面・本体・DB を実際につないで行うための手順を定める。期待結果は詳細設計書(第3.9版)を正とする。食い違いを見つけたら、NG として記録し、設計書と実装のどちらが正しいかを確認する。

- ST-20(評価環境)は段階6で EC2 を用意してから行うため、本書では扱わない。
- 予測値・提案数はサンプルデータと実行日で変わるため、本書では数値ではなく「何が変わるか」を確かめる。取込の件数は、手動テスト用のデータ(下記)で決まるため数値で示す。

## 1. 準備

コマンドは Git Bash で、リポジトリのルートをカレントにして実行する。環境の作り方(uv・`.venv`・`npm ci`・`backend/.env`)は `設計書/開発環境構築マニュアル.md` の手順 2〜6 を終えておくこと。

### 1.1 手動テスト専用の DB を作る

開発用の DB(`supermarket_dx`)や試験用の DB(`smdx_test`)とは分ける。試験用の DB は pytest が作り直すため使わない。

```bash
createdb -U postgres smdx_manual
```

- 以下、接続先を `postgresql://postgres@localhost:5432/smdx_manual` と書く。PostgreSQL 16 を別のポートで動かしている PC(例: 5433)は、ポートを読み替える。
- パスワードは URL に書かず、`pgpass.conf` か入力で渡す(開発環境構築マニュアル 7.2)。
- Docker Compose で動かす場合は `docker compose exec db createdb -U postgres smdx_manual` で作り、`backend/.env` の `DATABASE_URL` を一時的に `smdx_manual` に変えて本体を起動し直す(終わったら戻す)。

### 1.2 本体と画面を起動する

ターミナルを2つ開く。本体は環境変数 `DATABASE_URL` で接続先を `smdx_manual` に切り替える(`.env` より環境変数が優先される)。

```bash
# ターミナル1: 本体
cd app/backend
export DATABASE_URL=postgresql://postgres@localhost:5432/smdx_manual
../.venv/Scripts/python -m alembic upgrade head
../.venv/Scripts/python -m uvicorn --factory smdx_api.main:create_app --reload --port 8000
```

```bash
# ターミナル2: 画面
cd app/frontend
npm run dev
```

http://localhost:8000/health が `{"status":"ok"}` を返し、http://localhost:5173/login が開けばよい。

テストの途中で本体の環境変数を変えるとき(ST-02、ST-04 の上限、ST-15)は、ターミナル1を Ctrl+C で止め、`export` を足して `uvicorn` を実行し直す。

### 1.3 テスト用の利用者を作る

別のターミナルで、`DATABASE_URL` を同じく `smdx_manual` にして実行する。初期パスワード(8文字以上)は入力を求められるので、各自で決めて入力する。**パスワードは本書・リポジトリ・チャットに書かない。**

```bash
cd app/backend
export DATABASE_URL=postgresql://postgres@localhost:5432/smdx_manual
../.venv/Scripts/python -m smdx_api.commands create_user --login-id t_tencho --name 試験店長 --role manager
../.venv/Scripts/python -m smdx_api.commands create_user --login-id t_veg --name 青果担当 --role staff --departments VEG
../.venv/Scripts/python -m smdx_api.commands create_user --login-id t_fish --name 鮮魚担当 --role staff --departments FISH
../.venv/Scripts/python -m smdx_api.commands create_user --login-id t_deli --name 惣菜担当 --role staff --departments DELI
../.venv/Scripts/python -m smdx_api.commands create_user --login-id t_vegdeli --name 兼務担当 --role staff --departments VEG,DELI
```

| ログインID | 役割 | 所属部門 | 主に使うテスト |
|---|---|---|---|
| t_tencho | 店長 | ― | 商品マスタの取込、設定、カレンダー |
| t_veg | 担当者 | 青果 | 発注・承認 |
| t_fish | 担当者 | 鮮魚 | 他部門の拒否、在庫なしの警告 |
| t_deli | 担当者 | 惣菜 | 製造計画 |
| t_vegdeli | 担当者 | 青果・惣菜 | 初期画面(両方なら発注) |

### 1.4 土台のサンプルデータを入れる

研究用サンプルデータ(400日分・15品)を、**テストを行う日の前日**を終端日にして作り、投入する。下の日付は例(テスト日が 2026-10-30 の場合)。

```bash
cd app
.venv/Scripts/python -m smdx_sample --out sample_data/output --end-date 2026-10-29
cd backend
../.venv/Scripts/python -m smdx_api.commands import_sample --folder ../sample_data/output
```

- サンプルの在庫は各日の閉店時(20:00)の分だけなので、この時点では当日の在庫が無い(全商品に「在庫未取込」が付く)。
- 祝日を入れる場合は、内閣府の「国民の祝日」CSV(`syukujitsu.csv`)を取得して `import_holidays --file syukujitsu.csv` を実行する(無くてもテストはできる)。

### 1.5 手動テスト用のデータを作る

POS・在庫の日付をテストの日に合わせるため、スクリプトで作る(出力先 `テスト/手動テストデータ/output/` は Git に含めない)。テストを行う日に、リポジトリのルートで実行する。

```bash
app/.venv/Scripts/python テスト/手動テストデータ/make_data.py
```

| ファイル | 内容 | 取り込む画面の選択 |
|---|---|---|
| A_商品マスタ_追加とエラー行.csv | 新商品 VEG-101(販売実績なし)・VEG-102(リードタイム2日)と、不正な行5件 | 商品マスタ(店長) |
| B_POS_青果_前日_エラー行入り.csv | 前日の POS 5件と、不正な行7件 | POS・青果 |
| C_在庫_青果_当日.csv | 当日(作成時刻の5分前)の青果の在庫8品。A を先に取り込むこと | 在庫・青果 |
| D_廃棄_鮮魚_前日.csv | 前日の廃棄2件 | 廃棄・鮮魚 |
| E1〜E4_拒否_*.csv | 取込全体が拒否されるファイル(必須列なし・見出しの重複・閉じていない引用符・Shift_JIS) | POS・青果(E4 は商品マスタ) |
| F_BOMつき_引用符内の改行.csv | BOMつき UTF-8 で、商品名に改行を含む商品 VEG-108 | 商品マスタ(店長) |

在庫の基準日時はスクリプトを実行した時刻の5分前になる。テストを始める直前に作ること(後でもう一度実行すると基準日時が新しくなる)。

### 1.6 予測モデル(ST-16 を行う場合のみ)

モデルが無ければ本体はベースライン(前週同曜日)で予測する。ST-16 を行う場合だけ、開発環境構築マニュアル 9.4 の手順でモデルを作っておく(`backend/models/` にはまだ置かない)。

### 1.7 記録の仕方

各テストの表の「結果」に OK / NG を書く。NG のときは、画面の写し(スクリーンショット)、時刻、本体のログ(ターミナル1)の該当部分を残す。実施日・実施者・ブランチ(またはコミット)を下の表に書く。

| 実施日 | 実施者 | ブランチ・コミット | テスト日(--end-date の翌日) | 備考 |
|---|---|---|---|---|
| | | | | |

## 2. テストの順序

ST-04(取込)で入れたデータを後のテストが使うため、原則として番号順に行う。時刻に依存するテストがあるので、次の時間帯に行う。

- 営業時間(既定 10:00〜20:00)の中、できれば 11:00〜12:30 か 14:00〜15:30 に始める。ST-12 は、陳列残数を入れる時刻の直後の時間帯の製造開始(既定は各時間帯の1時間前)をまだ過ぎていないことが必要なため。
- 既定の発注締め時刻(閉店時刻 20:00)より前に行う。

### ST-06 修正と承認

### ST-10 2人の同時操作

通常のウィンドウ(A)と、シークレット(InPrivate)ウィンドウ(B)を使う(Cookie が別になる)。

| 手順 | 操作 | 期待結果 | 結果 |
|---|---|---|---|
